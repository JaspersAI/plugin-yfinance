# CLAUDE.md

The `yfinance` plugin for Jaspers Terminal, written against `@jaspers-ai/sdk`. The app loads it from a folder in `~/Jaspers/plugins/yfinance` (a clone of this repo, or an installed release) and rebuilds it on save. How plugins work, the SDK, and the app's side are in the terminal repo's CLAUDE.md. Onboarding offers this plugin to new users (`STARTER_PLUGINS` in the terminal), so it needs a release for them to get it.

## Commands

Node 24.

- `npm install`
- `npm run typecheck` — `tsc --noEmit`
- `npm test` — Node's test runner over `*.test.ts` and `server/*.test.ts`, which strips the types itself; no network
- `npm run smoke` — every tool once against the real Yahoo Finance, then the server over stdio; a line per call, exit 1 on any failure. Run it on the app's own Node for what the app sees: `ELECTRON_RUN_AS_NODE=1 <terminal>/node_modules/.bin/electron scripts/smoke.ts`
- `npm run package` — `build/yfinance-<version>.zip`, what a release attaches (about 5 MB: `@modelcontextprotocol/sdk` and `zod`); `fixtures/`, `scripts/`, and the tests stay out. The Release workflow runs it on a `v*` tag

Style: square, no rounded corners; `#e5e5e5` borders, `#737373` muted, green `#15803d` and red `#b91c1c` only for a number's sign.

## The plugin

### The connection and the client

- `yfinance/server` runs `server/main.ts` in the plugin's folder on the app's own Node (`command: ['node', …]`), since Yahoo Finance has no MCP server and no official API. No secret. `tools` names the fourteen below; `server/server.ts` registers them (`createServer({ fetch, sleep, now })`, all read-only, `annotations.readOnlyHint`), and its `instructions` say what the data is and how symbols look.
- `server/yahoo.ts` is the client, tested in `server/yahoo.test.ts` against a stand-in Yahoo. What it does was found by asking, from Electron 44's Node, on 2026-09-16:
  - The agent is `Mozilla/5.0 (compatible; JaspersTerminal-yfinance/1.0)`. A browser's full agent from Node gets 429 on every endpoint (Yahoo checks it against the TLS handshake); Node's default, curl's, python-requests', and yahoo-finance2's get 429 from getcrumb.
  - A session is the cookie `fc.yahoo.com` sets (answering 404, redirects not followed) and the crumb `query1…/v1/test/getcrumb` answers with it, as text: asking it for JSON gets a 406. One session per process, shared by concurrent askers. Only quote, quoteSummary, and options send `crumb` and the cookie; everything else goes without, and a 401 there asks once more with a session. A 401 with a session opens a new one (unless another asker already did) and asks once more.
  - A 429, a 5xx, or a network failure is asked once more after 800 ms; then a `YahooError` in words (`RATE_LIMITED`, `Yahoo Finance answered 503 for …`, `could not be reached for …: <cause>`). Yahoo's own `error.description` (in any `{ <key>: { result: null, error } }` body, even a 200) becomes `Yahoo Finance: <description>`, never retried.
  - Four requests at once (`limiter`, a finishing task hands its place on), 20 s each. Answers are kept per URL without the crumb for the caller's `ttl`, at most 300, a failure dropped at once.
- `format.ts` (`display` with a true minus for the views, `plain` with a hyphen for the model's text, `smallPercent`) and `values.ts` (`num` unwraps `{ raw, fmt }`, `percentOf` turns a fraction into percent rounded past float noise) are shared by the server and the views, so they touch neither Node nor the DOM.

### The tools and sources

Every tool answers text for the model (a head line, then lines; `capped` near 30,000 characters, saying what was left out) and `structuredContent` with a `rows` array, since the app hands a view only rows (the dataset) and the rest (meta). A field whose name ends in `Percent` is in percent (7.97 is 7.97%). The readers are pure and tested on trimmed real answers in `fixtures/` (taken 2026-09-16; `server/*.test.ts`); `server/server.test.ts` drives the server through an in-memory MCP client against a stand-in Yahoo that answers with them.

- `server/quotes.ts`: `search` (v1 search, quotes only), `get_quote` (v7 quote, up to 50 symbols, `missing` named; none found is a refusal), `get_news` (v1 search, news only, newest first), `get_market_summary` (v6 marketSummary, short names), `get_market_movers` (`MOVER_LISTS`: gainers, losers, most_active through `v1/finance/screener/predefined/saved`; trending through `v1/finance/trending/US` and one quote call, kept in Yahoo's order; and the saved screens undervalued_growth, growth_technology, aggressive_small_caps, small_cap_gainers, undervalued_large_caps; `most_shorted_stocks` answered 500 and is not offered). v7's percentages are already percent; its `dividendYield` is percent, the trailing one a fraction.
- `server/history.ts`: `get_price_history` (v8 chart with `events=div,splits`, a range or start/end days, `period2` for an open end the next UTC midnight). Bars on the market's clock from `gmtoffset` (a day, or `YYYY-MM-DD HH:MM` intraday), bars with no close dropped, prices rounded to the price hint plus two; the text lists the latest 400 as CSV under a summary.
- `server/company.ts`: quoteSummary with `formatted=false`, one tool per group of modules (`MODULES`): `get_company_profile` (officers as rows; ISS governance risk), `get_key_statistics` (`STATS`, 64 figures in nine groups, each row with its unit and display; a profitability figure of exactly 0 is Yahoo's placeholder and left out), `get_earnings` (the last four quarters newest first with their fiscal labels from `earningsChart`, the next date and its estimates from `calendarEvents`, `earningsTrend` per period, annual revenue and earnings), `get_analyst_ratings` (targets, consensus, the monthly mix, rating changes newest first with a 0 target read as none), `get_holders` (institutions as rows; funds, insiders, trades, net purchases), `get_fund_holdings` (a stock is refused; `equityHoldings` is left out, its values read as reciprocals; a turnover of 0 is none; net assets from `totalAssets`).
- `server/financials.ts`: `get_financials` from `ws/fundamentals-timeseries` (quoteSummary's statement modules have been mostly empty since 2023). `LINES` per statement in statement order, `highlight` for the key ones; `timeseriesQuery` asks for all of them with the frequency prefix, `period2` the next UTC midnight so the URL holds for a day. The columns are the dates of the statement's lead line (revenue, total assets, operating cash flow), latest first, up to eight; trailing keeps only `TTM` entries; a trailing balance sheet is refused before Yahoo is asked.
- `server/options.ts`: `get_options_chain` (v7 options). An asked expiration is checked against the listed days (the nearest five are named when it is not one) and asked for by its day at 00:00 UTC in seconds; the rows are the strikes nearest the price, calls and puts side by side, with totals, put/call ratios, and the strike at the money with its mids.
- `plugin.tsx` makes each tool a source with no description of its own (the model reads the server's, prefixed `Source yfinance/<name> on connection yfinance/server.`) and a `ttlMs` for how long its data lasts: `search`, `quote`, `history`, `profile`, `statistics`, `financials`, `earnings`, `analysts`, `holders`, `options`, `news`, `market-summary`, `movers`, `fund`. The orchestrator calls them as `yfinance__quote` and the rest; research analysts reach them by naming `yfinance/server` in their `connections`.

### The views

Five views, each reading the whole panel state with `useData('workspaces/…/panels/<id>/state')` (the `ChartView` pattern) and writing keys through `bridge.setState` in order (`useStateWriter`). `views.ts` is their pure half, tested in `views.test.ts` with runs built from the fixtures: state readers, outputs under the 4,096 bytes a publish may take, `summarize` functions, and the small reckonings (`position`, `ratingMix`, `ratingAction`, `overviewStats`). `shared.tsx` has the bar (with a `Yahoo Finance ↗` link to the symbol's page through `openLink`), the symbol field (Enter read off the key; the frame has no `allow-forms`), `Section` (a run's error in Yahoo's words before its content), `Signed`, `RangeBar`, and `useEvery`.

- `yfinance/overview`, Company, `{ symbol }`: quote, statistics, analysts (limit 5), earnings, profile, and for an ETF or mutual fund (`isFund` on the quote's type) the fund run with its figures, top holdings, and sector bars. A section with nothing and no error stays out. Output: the headline figures, target, consensus, next earnings, sector, industry, and `errors` naming any run that failed.
- `yfinance/watchlist`, `{ symbols }` up to 30: one quote run, fresh every minute; the field adds (upper-cased, deduplicated) and × removes, both writing the whole list. Output: count, missing, each symbol's price and percent.
- `yfinance/markets`, `{ list }`: market summary tiles (a 2 px sign line on top) and the movers list (25), both fresh every minute; tabs for the four lists, a Screens menu for the saved ones. Output: the list, its title and total, sixteen tiles, the top ten.
- `yfinance/financials`, `{ symbol, statement, frequency }`: toggles; TTM is disabled for a balance sheet, and choosing Balance sheet on TTM writes `frequency: annual` first. Output: periods and the key lines' values by label.
- `yfinance/options`, `{ symbol, expiration, strikes }`: the expiration menu from the run's list, a strikes menu, calls | strike | puts with the in-the-money side shaded and a price rule row, fresh every minute; a new symbol writes `expiration: null` before `symbol`. Output: expiration, the listed dates, the underlying, the money strike, put/call ratios.
- The orchestrator drives them by state: `place_view { view: 'yfinance/overview', state: { symbol: 'NVDA' } }`, `set panels/e1/state/symbols ["AAPL","MSFT"]`, `set panels/e2/state/list trending`, `set panels/e3/state { symbol: 'MSFT', statement: 'cashflow', frequency: 'quarterly' }`, `set panels/e4/state/expiration 2026-09-25`. Each view's `instructions` (`instructions.ts`) say what its output holds and to call the sources for more.

### Verified

On 2026-09-16, in a sandboxed terminal (driver with its own `CDP_PORT`, `USER_DATA_DIR`, and `JASPERS_HOME`): the release zip installed from a file, the connection was ready with fourteen tools in half a second, all five views drew live data and published their outputs and summaries, state changes and real clicks and typing (a symbol added, a tab chosen) worked, and a scripted OpenAI-compatible mock model on 127.0.0.1:8788 called `yfinance__quote` and placed the Company view, whose instructions then reached the prompt. Not reachable from here: Yahoo's EU consent flow, and an earnings calendar (`v1/finance/calendar/earnings` answered 404).
